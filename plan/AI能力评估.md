# AI 能力评估：Phase 1 中 AI 能承担多少工作

> 评估方法：逐任务对照 AI 的实际能力边界，给出可替代比例和具体示例。

---

## 一、总览

```
Phase 1 总工时: 68h
├── AI 可独立完成主体 (人工仅审查) ........ 18h (26%)
├── AI 可完成大部分 (人工少量修改) ........ 15h (22%)
├── AI 辅助 (人工为主，AI提速) ............ 12h (18%)
├── 必须人工 ............................... 16h (24%)
└── 缓冲 ................................... 7h (10%)
```

**核心结论：AI 可以承担约 48% 的工作量（33h 等效产出），但这些集中在纯代码和数据配置上。其余 52% 必须人工完成，主要是视觉判断和游戏内测试。**

换算成实际意义：68h 的计划中，**你的有效人工时间约为 42-48 小时**，AI 帮你省掉了约 20-26 小时的重复性工作。

### AI 能做到 90%+ 质量的任务

这些任务的特点是**输入和输出都是纯文本，有明确的规范约束**：

```gdscript
# 输入："参考 Tank.gd，创建一个陆战兵 Marine，地面单位，速度2.5，
#        攻击力3，射程6，对地攻击，默认动作为 WaitingForTargets"

# AI 输出（直接可用）：
extends "res://source/match/units/Unit.gd"

const WaitingForTargets = preload("res://source/match/units/actions/WaitingForTargets.gd")

func _ready():
    await super()
    action_changed.connect(_on_action_changed)
    action = WaitingForTargets.new()

func _on_action_changed(new_action):
    if new_action == null:
        action = WaitingForTargets.new()
```

### AI 能做到 50-80% 的任务

特点是**逻辑复杂但有规律可循**：

- **技能逻辑**：AI 理解"点目标AOE""单位目标DoT""召唤"等模式，能写出骨架代码。但参数调整（范围多大、伤害多少）需要人工在游戏里测试后反馈
- **粒子配置**：AI 知道 "爆炸=球体扩散+橙红渐变+40粒子"，但具体的 lifetime、gravity、scale_curve 需要人在编辑器中看着调
- **UI 布局**：AI 能写 Control 节点层级，但像素对齐需要人工

### AI 几乎帮不上忙的任务

特点是**必须依赖视觉反馈或编辑器交互**：

| 任务 | 为什么 AI 做不到 |
|------|-----------------|
| 模型拼装（选Kenney模型+组合） | 需要"看"模型长什么样，AI 无法浏览和判断视觉效果 |
| VFX 调参 | 需要反复预览粒子效果，微调参数直到好看 |
| 场景布局（地图、单位位置） | 100% 编辑器拖拽操作 |
| 游戏测试 | 需要运行 Godot 引擎，观察行为，判断"这算不算bug" |
| 模型缩放/旋转微调 | 需要看到实际比例是否合适 |
| 颜色/材质最终确认 | 需要在引擎渲染窗口中判断 |

## 四、AI 对整体效率的真实影响

### 按任务性质的效率提升

```
                   计划人时    AI后人时    节省
纯代码任务           25h   →    8h      17h (68%)
数据配置任务          8h   →    2h       6h (75%)
人机协作任务         12h   →    8h       4h (33%)
必须人工任务         16h   →   15h       1h (6%)
缓冲                 7h   →    5h       2h
────────────────────────────────────────────
合计                68h   →   38h      30h (44%)
```

### 这意味着什么

**AI 不是把 68h 缩短为 30h。实际效果是**：

1. **同样的时间，产出更多**：68h 里你能完成原本需要 ~100h 的工作量
2. **重复性工作消失**：写6个单位的 .gd 脚本从 3h 变成 10 分钟（AI 批量生成）
3. **瓶颈转移到视觉任务**：代码不再是瓶颈，模型拼装和 VFX 调参成为新的瓶颈
4. **测试时间不能被 AI 压缩**：12h 测试时间只能靠自己跑游戏

### 实际建议的工作分配

```
你的时间应该花在：
  ✅ 运行游戏、测试、发现问题             (38h中占 12h)
  ✅ 在编辑器中拼装模型、调VFX            (38h中占 15h)
  ✅ 审核 AI 生成的代码，微调参数          (38h中占 6h)
  ✅ 设计决策（数值、机制）               (38h中占 3h)
  ✅ 缓冲                                (38h中占 2h)

AI 帮你省掉的时间：
  ✅ 写 .gd 脚本（6个单位+8个技能+Hero基类+冷却系统）
  ✅ 写 MatchConstants 配置字典
  ✅ 写 tscn 场景文件骨架
  ✅ 写粒子系统的初始参数
  ✅ 批量生成重复代码
```

## 五、高效的 AI 协作模式

### 模式 1：AI 批量生成 + 人工逐个审核

```
适用：6个单位脚本、8个技能脚本、MatchConstants 配置

流程：
  1. 人工写好第一个单位的完整脚本（如 Marine.gd）
  2. 告诉 AI："参考 Marine.gd，生成其余5个单位的脚本，差异如下..."
  3. AI 一次性生成全部
  4. 人工逐文件快速扫一眼（每个30秒）+ 在 Godot 中跑一遍
```

### 模式 2：AI 写初版 + 人工在编辑器中调

```
适用：tscn 场景文件、粒子配置

流程：
  1. 描述需要的场景结构给 AI
  2. AI 生成 .tscn 文本
  3. 人工在 Godot 中打开，拖入正确的 Kenney 模型引用，调 Transform
```

### 模式 3：人工描述问题 + AI 诊断 + 人工验证

```
适用：Bug 修复

流程：
  1. 在 Godot 中发现 bug，截图或复制报错信息
  2. 告诉 AI 现象和报错
  3. AI 定位代码问题并生成修复
  4. 人工应用修复，重新运行验证
```

### 模式 4：AI 不能做的，不要浪费时间尝试

```
❌ 不要尝试让 AI 帮你选哪个 Kenney 模型好看 → 它看不到
❌ 不要尝试让 AI 帮你调粒子颜色 → 它看不到
❌ 不要尝试让 AI 帮你测游戏 → 它无法运行 Godot
✅ 但可以让 AI 给你列出所有红色系的粒子配色方案 → 你选一个，然后在编辑器中调
```

## 六、总结

**AI 能承担 Phase 1 约 44% 的工作量（30h 等效产出），集中体现在：**

| 能力等级 | 代表任务 | 节省时间 |
|---------|---------|---------|
| 90%+ 替代 | 单位脚本、配置字典、tscn骨架、简单逻辑 | 23h |
| 50-80% 替代 | 技能逻辑、UI代码、粒子初始参数 | 6h |
| 几乎无效 | 模型拼装、VFX调参、场景布局、游戏测试 | 1h |

**实际执行中，68h 的计划你大约需要投入 38-45h 的有效工作时间**，剩下的 AI 帮你填满。

最大的风险不在代码——AI 写 GDScript 的能力足够强。最大风险在 **视觉产出效率**（15h 模型+VFX 基本全靠人工）和**测试覆盖率**（12h 测试时间无法用 AI 压缩）。如果这两个环节卡住，进度就会落后。
