### 关键认知

**美术工作量 ≠ 3D建模**。模板已证明：Tank = craft_cargoB + craft_miner 两个Kenney模型的组合。Helicopter的螺旋桨是用BoxMesh+CylinderMesh程序化生成的。Phase 1的所有"美术"，本质上都是**在Godot编辑器里拖拽、缩放、组合已有模型，加上粒子系统和材质调整**。真正需要外部工具（Blender）建模的情况极少。

### 任务 1.2：Hero.gd 英雄基类（8h，程序）

**时间段**：周四~周五晚上（5h）+ 周六下午（3h）

**基于模板的改动**：

```
新建文件：
  source/match/units/Hero.gd           ← 继承 Unit.gd
  source/match/units/traits/HeroUI.tscn ← 英雄专属UI（头像+经验条+技能栏）
  source/match/units/traits/HeroUI.gd

修改文件：
  source/match/units/Unit.gd           ← 可能需要暴露一些方法供Hero重写
  source/match/MatchSignals.gd         ← 新增 hero_leveled_up, hero_skill_used 信号
  source/match/MatchConstants.gd       ← 新增 HERO_PROPERTIES, EXPERIENCE_CURVE
```

**Hero.gd 核心新增属性**：

```gdscript
extends "res://source/match/units/Unit.gd"

var experience = 0
var level = 1
var skills = []           # Array[PackedScene] - 技能场景引用
var skill_cooldowns = {}  # 每个技能的剩余冷却时间
var inventory = []        # 预留：道具栏

signal leveled_up(new_level)
signal experience_gained(amount)

func gain_experience(amount: int):
    experience += amount
    experience_gained.emit(amount)
    var next_level_xp = Constants.Match.Heroes.EXPERIENCE_CURVE.get(level + 1, INF)
    if experience >= next_level_xp:
        level_up()

func level_up():
    level += 1
    # 弹出技能选择UI（Phase 2实现，Phase 1先自动升级预设技能）
    leveled_up.emit(level)

func use_skill(slot: int, target) -> bool:
    # 检查冷却、资源、范围，实例化SkillAction
    pass
```

**实现要点**：
- Hero 复用 Unit 的所有 Trait（Movement、HealthBar 等）
- 新增 `HeroUI` Trait：在屏幕底部显示英雄头像+经验条+技能栏（类似 WC3 右上角）
- `experience` 通过监听 `MatchSignals.unit_died` 来增加（击杀者获得经验）
- 技能冷却用 `_process(delta)` 递减 `skill_cooldowns`

### 任务 1.3：SkillAction.gd 技能基类 + AbilityCooldown Trait（6.5h，程序）

**时间段**：周日上午（3.5h）+ 周日下午（3h）

**新建文件**：

```

source/match/units/traits/AbilityCooldown.tscn   ← 技能图标上的冷却遮罩
source/match/units/traits/AbilityCooldown.gd
```

**SkillAction.gd 设计**：

```gdscript
extends "res://source/match/units/actions/Action.gd"

class_name SkillAction

@export var skill_name: String = ""
@export var cooldown: float = 10.0
@export var mana_cost: int = 0     # 预留Phase 3法力系统
@export var cast_range: float = 8.0
@export var icon: Texture2D        # 技能图标

var _caster: Unit = null

func _init(caster: Unit):
    _caster = caster

func execute(target) -> bool:
    # 子类重写，执行具体技能逻辑
    return true

func can_cast() -> bool:
    if _caster.skill_cooldowns.get(skill_name, 0) > 0:
        return false
    # 检查资源、距离等
    return true
```

**AbilityCooldown Trait**：
- 挂在技能图标UI上
- 一个半透明遮罩从顶部覆盖到当前冷却位置（类似 WC3 的时钟遮罩）
- 用 `TextureProgressBar` 或自定义 `draw_rect` 实现

## 七、美术制作指南（给不会建模的开发者）

### 7.1 模型拼装工作流

```
步骤1：浏览 Kenney 模型库 → 找到外观接近的模型
步骤2：在 Godot 编辑器中创建 Geometry 节点
步骤3：拖入1-3个 Kenney 模型作为子节点
步骤4：调整每个子节点的 Transform（位置、旋转、缩放）
步骤5：确保模型中有金色 (0.99,0.81,0.48) 区域 → 会被自动替换为玩家颜色
步骤6：添加 CollisionShape3D、各 Trait 子节点
步骤7：保存为 .tscn → 完成
```

**实战示例——联邦英雄（指挥官）**：
```
Geometry (Node3D)
├── astronautA.glb         ← 身体，scale=1.0
├── craft_speederA.glb     ← 背包/装甲，scale=0.3, 放在背后
├── weapon_rifle.glb       ← 武器，scale=0.8, 放在右手位置
└── ProjectileOrigin (Marker3D) ← 弹射物出生点
```

**实战示例——虫群英雄（巢虫领主）**：
```
Geometry (Node3D)
├── alien.glb              ← 身体，scale=2.0
├── rock_crystals.glb      ← 背部的晶体装甲，scale=1.5
├── bones.glb              ← 额外肢体装饰，scale=1.2
└── ProjectileOrigin (Marker3D)
```

### 7.2 VFX 制作工作流

全部使用 Godot 内置的 **GPUParticles3D** 节点：

```
英雄技能 VFX 模板结构：
SkillVFX (Node3D, 作为技能Action的子节点)
├── GPUParticles3D (爆炸/冲击)
│   ├── emitting = false (由代码触发)
│   ├── amount = 30
│   ├── lifetime = 0.5s
│   └── process_material = ParticleProcessMaterial
├── GPUParticles3D (拖尾/持续效果)
└── OmniLight3D (闪光，持续0.3s)
```

**常用特效配方**：
| 效果 | 粒子形状 | 方向 | 颜色渐变 | 数量 |
|------|---------|------|---------|------|
| 爆炸 | Sphere, radius 0.5→2.0 | 向外 | 橙→红→透明 | 40 |
| 激光 | Box, 细长条 | 向下 | 白→蓝→透明 | 5 |
| 毒雾 | Sphere, radius 1.0→3.0 | 上浮 | 绿→黄→透明 | 60 |
| 护盾 | Sphere, radius 固定 | 无 | 蓝→浅蓝→透明 | 20 |
| 钻地 | Box, 宽扁 | 向上 | 棕→灰→透明 | 30 |

### 7.3 时间投入评估

| 一个单位的完整美术 | 纯拼装（已有合适模型） | 需要创意外观 | 需要自定义几何体 |
|-------------------|---------------------|------------|----------------|
| 模型拼装 | 0.5-1h | 1-2h | 3-5h (需Blender) |
| .tscn 场景搭建 | 0.5h | 0.5h | 0.5h |
| VFX（如有） | 0.5h | 1h | 1-2h |
| **合计** | **1-2h** | **2.5-4.5h** | **4.5-7.5h** |

Phase 1 全部走"纯拼装"路线，每个单位控制在 **1-2小时内完成**。

## 八、风险点与缓解措施

| 风险 | 概率 | 缓解措施 |
|------|------|---------|
| 英雄技能系统比预期复杂 | 中 | Phase 1 只做"发射弹射物"和"修改属性"两类技能，不做位移、召唤物控制等复杂逻辑 |
| 拼装不出好看的模型 | 中 | 接受"能看就行"的标准。独立RTS玩家对画质容忍度高。Steam上很多成功RTS用的是更简陋的模型 |
| 集成时发现架构冲突 | 中 | Hero继承Unit，SkillAction继承Action——只要基类设计不变，不会有大问题 |
| AI不使用新单位 | 高 | Phase 1 只要求AI能生产基础单位和进攻。AI优化放在Phase 5 |
| 第3周测试时间不够 | 高 | 12h 测试时间是硬性安排，不可削减。如果前面进度落后，削减的是新单位数量（3→2），不是测试时间 |
| 粒子效果性能差 | 低 | GPUParticles3D 在现代硬件上效率很高。限制同时存在的粒子数（< 5000） |
